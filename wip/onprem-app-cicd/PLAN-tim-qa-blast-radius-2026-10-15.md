# Anything Tim can do to QA — blast radius and the way forward
2026-10-15

**Verdict.** QA survives the two things Tim does most often (edit an applied file, add a file
under an excluded path). **Four classes still take QA red, and two make it silently wrong.**
Every red one has the same shape: the applier is a Sync hook at wave 0 under `set -euo
pipefail`, so *one* bad file fails the *whole* Application — and then
[[failed-hook-job-makes-sync-a-noop]] means the next sync replays the failure in 0s and
recovery needs a human writing `.operation`. That human is Doke. That is the thing to remove.

**The fix is not another cluster flag.** Every red row below is detectable from Tim's PR, with
no cluster access and no secrets, because `apply.sh` already has `DRY_RUN=true`. Move the
judgement to PR time and QA stops being where he finds out.

Rows 5–9 are one bug with four doors: **a per-file problem fails the environment.**

## The way forward — ranked

**1. A required PR check in `usxpressinc/risingwave-poc` that dry-runs the applier for every
environment.** Closes 5, 6, 9 and most of 7 at PR time. `DRY_RUN=true` already renders and
hashes without applying. It needs one new artefact: a committed fixture of each environment's
placeholder **NAMES** — no values, nothing secret — generated by the platform repo from
`values-<env>.yaml` plus the ExternalSecret key list. The check renders every discovered file
against each env's name set and fails the PR naming the file and the missing `%KEY%`.
This is the whole answer to "it must work no issue": he finds out in his own PR.

**2. An idempotency lint in the same check.** Every `CREATE` in a `.rw`/`.sql` must be
`IF NOT EXISTS` or `OR REPLACE`. This is what makes `REAPPLY_CHANGED=true` *safe* rather than
merely *enabled* — today QA will happily re-run a `CREATE SOURCE` that cannot survive a second
run. Closes 7 and 9 properly.

**3. Normalise comments and whitespace out before hashing.** Row 2 stops rebuilding sources
for a typo fix. Shrinks the re-apply blast radius to real changes.

**4. Settle the double-declared key.** Row 10 is the worst class here — he edits, nothing
happens, nothing reports it. Delete `KAFKA_TOPIC_ACTIVE_RESOURCE` from one side (Idris's owed
PR) and add a check that fails when a key appears in both the ConfigMap and `<env>.env`.

**5. An exclusion self-test inside `apply.sh`.** Each alternative in `EXCLUDE_RE` must match
≥1 discovered path, else say so loudly. Makes the regex-that-matched-nothing impossible
([[validator-checks-every-value-not-the-selected-ones]], [[a-guard-can-measure-the-wrong-thing]]).
The stale `deploy/overlays/qa/CUTOVER_SCOPE.md` — which still publishes a regex matching no
real path — is the likely origin and should be deleted in the same PR.

**6. Let a failed hook recover itself.** `syncPolicy.retry` on QA's `app-risingwave`, so a red
hook does not need Doke writing `.operation`. This is the item that literally matches
"without needing me".

**7. CODEOWNERS on `build-sql-image.yml`.** Row 12 becomes a review instead of a surprise.

Order: 1 and 2 ship together as one PR check and are zero-risk to any cluster (new workflow
file in his repo, new fixture in ours). 3, 4, 5 are applier/values changes and go
QA2 → dev → QA behind a flag. 6 is one field. 7 is one file.

## Tested and killed

- **"An allowlist of applied files."** Withdrawn again, same reason as 10-14: a new file would
  be *silently ignored* — a green sync over code nobody runs, the failure family that has cost
  this system the most. Loud red beats silent skip. The answer is to move the red earlier, not
  to mute it.
- **"Make `apply.sh` exit 0 on a bad file."** Killed: that is Argo reporting Succeeded over a
  file that never applied — [[adjacent-step-green-signals]] by construction.
- **"Tim's SQL is safe because dev ran the same digest."** Killed by row 8: the digest travels,
  the topics, tables and ACLs do not.

## Traps

- Every red row produces the **same** symptom — a failed hook with no Job and no pod, because
  Argo deletes it either way. `.status.operationState.syncResult` is the only record.
- The second sync after any of them returns in 0s replaying the first failure. Compare
  `startedAt` with the failed run before believing a retry.
- Fixing a value and un-excluding a path in one PR fails the whole hook: `apply.sh` rejects a
  **missing OR empty** value, so the value must be non-empty *before* the exclusion is dropped.

## 2026-10-15 — the shipped applier has a DIFFERENT ARCHITECTURE from the draft

There is **no `render()` function** in `iaac-risingwave-cicd/build/apply.sh`. Every reference
to "render" is a temp file and an inline substitution:

    171: rendered=$(mktemp)
    172: trap 'rm -f "$rendered"' EXIT
    178:   rendered_content=$(<"$f")
    181:   rendered_content="${rendered_content//"$token"/${!var}}"
    183:   printf '%s\n' "$rendered_content" > "$rendered"
    184:   sha=$(sha256sum "$rendered" | cut -d' ' -f1)

So the draft's `render()` — the `missing=()` array, the named `UNRESOLVED` block, `return 1` —
**is not what runs.** Everything this note said about the refusal path was read from the wrong
architecture, not merely the wrong copy. [[edited-copy-is-not-the-shipped-copy]] one level
deeper: the two files do not just differ in content, they differ in shape, so a line number or
a function name from one says nothing about the other.

What survives unchanged: `set -euo pipefail` (line 12), the `**` + `sort` discovery (60/62),
the hash is of the **rendered** content (184), and `ON_ERROR_STOP` aborts on a SQL error.
Rows 1-4, 7, 9-14 of the action table stand on those.

⛔ **Still unread, and now the only open question: what an unresolved placeholder does.**
`${!var}` at line 181 under `set -u` aborts with `line 181: var: unbound variable` — no file
name, no key name — *unless* lines 179-180 guard it. The findings record that the applier
"rejects a missing OR empty value", so a guard exists somewhere; its form decides whether
rows 5, 6 and 8 fail the file or the environment. Read 160-220.

⚠️ The rendered content is written **to disk** (line 171), so the applier needs a writable
`/tmp` — [[readonly-rootfs-needs-a-tmp-volume]], which already cost QA weeks. The temp file
holds credentials in plaintext; the `EXIT` trap is the only thing removing it.

## ⛔ SETTLED — there is no placeholder validation in the shipped applier

Lines 177-185, read verbatim:

    rendered_content=$(<"$f")
    while IFS= read -r token; do
      var="${token:1:${#token}-2}"
      rendered_content="${rendered_content//"$token"/${!var}}"
    done < <(grep -oE '%[A-Z][A-Z0-9_]*%' "$f" | sort -u)

No `missing` array. No `-z` test. No `UNRESOLVED` message. No `return 1`. The only thing
standing between a bad value and the database is bash's own `set -u`, and it only covers half
the cases:

| Value | What bash does | Result |
|---|---|---|
| **unset** | `set -u` fires on `${!var}` | `line 181: FOO: unbound variable` — whole run dies. No file name, no key name |
| **set but empty** | `${!var}` → `''`, **no error** | DDL applied with an empty string, hashed, and **recorded in `pipeline_applied` as a success** |

**The empty case is the worst thing in this investigation.** `[[eso-writes-partial-secrets]]`
means a `SecretSyncedError` still writes the keys it *could* resolve — so a partial secret
plus this applier applies DDL with empty topics or empty credentials, records it green, and
leaves no trace but the object itself. When the real value lands the hash changes, so on an
environment with `REAPPLY_CHANGED=false` it is then **REFUSED forever**.

This retroactively explains why checking QA's 13 keys for *emptiness* rather than `Ready`
mattered so much on 10-14. That was the only thing between QA and silently-empty DDL.

### And the regex is wider than the draft's
`%[A-Z][A-Z0-9_]*%` — one character minimum, where the draft required two. `%` is SQL's
`LIKE` wildcard, so **`WHERE x LIKE '%ABC%'` is read as the placeholder `%ABC%`** and aborts
the run with `ABC: unbound variable`. New row in the action table, and entirely invisible in
review.
