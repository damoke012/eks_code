## Traps, measured

* **An immutable tag means a re-run cannot rebuild an unchanged commit**, and a changed
  BASE image can never reach an unchanged source commit. Republishing the applier needed
  a commit in Tim's repo PLUS an explicit dispatch, because his build filters on `paths:`
  and an empty commit matches nothing.
* **An expired SSO session reads as absence.** It made the check print two FAILs about
  objects that were present and healthy, and I concluded QA ran the kustomize overlay. QA
  has been on the chart all along.
* **Two copies of `apply.sh`.** Dev runs `iaac-risingwave-cicd`'s via `FROM sql-applier`;
  QA and prod run `risingwave-pipeline`'s own. Behaviour measured on dev is not evidence
  about QA.
* **`-z` cannot tell unset from empty**, so "present-and-empty" bought nothing.
* **QA has a DATABASE `postgres` but no ROLE `postgres`.** Connecting as `postgres` fails
  with `role "postgres" does not exist`, which reads like a dead server. The admin is
  `risingwave`, and it IS superuser — so the bootstrap hook works on QA unchanged.
* **Argo deletes the sync-hook Job on success and on failure**, so the only durable record
  is `operationState.syncResult`. A plain Job run for debugging must be deleted afterwards:
  a leftover `etl-pipeline-debug` on a superseded digest was the only visible workload in
  `app-risingwave` two hours later.
* **`app-risingwave` ≠ `risingwave`.** The ETL's ConfigMaps and hook live in the former,
  RisingWave and Postgres in the latter. Querying the wrong one returns NotFound.
