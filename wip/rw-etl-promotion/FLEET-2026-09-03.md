## Tested and killed

- **"12/12 Running" as a health check.** A crashlooping pod shows Running between backoffs.
  Prod's console read as healthy for two days that way.
- **A cumulative restart count as evidence of a live fault.** It never falls, so 532
  restarts cannot distinguish crashing now from settled hours ago. Uptime of the current
  container instance is the discriminator.
- **`state.running.startedAt` alone.** A container in CrashLoopBackOff is in `state.waiting`
  with no `startedAt`, so a healthy sidecar in the same pod masked it entirely — this is how
  prometheus-server reported "stable 133h" while restarting every few minutes.
  `lastState.terminated.finishedAt` is the field that says when a container last died.

## Traps

- **An unreachable cluster is not a healthy one.** op-qa was UNKNOWN for most of the day on
  an expired 8-hour SSO session — `aws sso login --profile op-qa` (`usx-qa` is the account
  profile for Terraform, not cluster access).
- **`onprem_resolve_ctx` used to take `head -1` of its candidates**, so one stale kubeconfig
  condemned a cluster that a second, working candidate served. Fixed; every candidate is
  tried and all the safety assertions still run on whichever is used.
- **A WARN folded into "ok" reads as healthy** in the summary line, which is the line people
  actually read. Counted separately now.
